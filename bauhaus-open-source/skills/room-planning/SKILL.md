# 房间规划与软装布局

先找到仓库根目录的 `public/data.json`、`src/house.js`、`src/collision.js`、`src/finishes.js` 和 README。用户在其他项目调用时先确认实际数据入口，不依赖作者电脑路径。

## 规划输入

- 用户明确的风格、房间用途、预算、要保留的家具与禁止移动的结构。
- 户型图和已确认尺寸；把实测值、图中标注、估算分别记录。
- 当前 `layout` 和 `catalog`，以及参考图片可见的材质、轮廓、分区关系。

有已有户型时，以它为边界。用户要求保持窗位和房间尺寸，就冻结 `walls/windows/doors/floor` 并在完成后比较。若原资料冲突，先继续不依赖冲突项的工作，并说明哪项尺寸需核实。不要把截图比例当成毫米尺寸。

## 执行

1. 按房间建立用途、墙色、材质、照明、主家具与壁面陈设清单；整间改色要覆盖该房间全部相应墙面。
2. 先布局大件与固定设施，预留门扇开启和人行空间，再加茶几、灯、书架、唱片、摆件。通道尺寸是项目约束，不冒充建筑规范核定。
3. 查已有 `catalog`，同类候选保留在物品库，默认场景选择适量实例。不要为了“全部可摆放”把所有候选塞进默认场景。
4. 缺少合适商品时输出选品任务：品类、位置、最大包络、材质、颜色、预算及参考特征。若 `product-research` 已安装，使用它；否则按同等记录方式搜索，不强依赖特定连接器。
5. 每个模型必须对应具体商品图片和规格，先看图再建模。柜门、沙发扶手、金属脚架、开孔等辨识特征不同，应分专用模型，不用通用方块替代。
6. `dims` 用宽/深/高米制；折叠毛巾、床品下垂、组合隔断等分别说明商品规格和场景包络。未知值允许暂定，但用 `estimated` 和 `sizeText` 明示。
7. 挂墙物体贴合墙面；台面摆件有支撑；吊灯有吊点；植物不堵门。对疑似浮空或穿模实例先移动或删除默认摆放，保留库中商品。
8. 在原始布局的可撤销副本中修改；保持样板与放置模式一致的实时画质，并保留编辑导入导出。

## 输出与验收

按 [规划记录模板](references/planning-template.md) 保存约束和变更，不需要重复写用户已确认的信息。修改完成运行仓库的 `npm run check` 和 `npm run build`；浏览器检查走动、门、墙色和家具支撑。脚本只证明包络/路径等有限性质，模型是否像商品必须视觉比对。

交付应包含修改后的 `layout.placed`、新增商品引用、未核尺寸清单、变更前后的结构比较、实际截图和复现步骤。只报告已测试的功能，不把概念设计描述为施工验收结果。
