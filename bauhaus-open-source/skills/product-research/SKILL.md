# 商品搜索与图片核对

读取用户当前选品需求、已有 `public/data.json` 和 [记录格式](references/product-record.md)。优先复用清单已有条目，保留当前品牌与真实规格；不要为了凑造型替换成用户排除的平台或风格。

## 检索与证据

1. 对参考图片先列可见特征：轮廓、扶手/靠背/脚架、材质、颜色、孔位、尺寸比例和安装方式。不能从图片猜出品牌就写“同款”。
2. 查目录是否已有商品，再使用当前可用的搜索工具或浏览器。用户指定京东就优先京东；关键词由品类、特征、材料、大小组成。需要三种候选时选择有真实差异的款式，不重复同一 SKU。
3. 打开可读的商品页并查看实际图片，核对所选 SKU/颜色/尺寸。只有搜索列表可读时标记证据级别为 `search-listing`，不要描述为详情页已核。
4. 保留商品页 URL、SKU、商家、图片来源 URL、观察日期和所选规格。价格写明标价/活动价/补贴价，未核实优惠条件不得当成最终结算价。
5. 评论内容、评价量、销量与种草数分别记录。没有打开评论正文就写“未读取评论正文”；不编造好评率，也不从商家宣传推断买家反馈。
6. 确认尺寸是宽深高、单件或套装、展开或折叠尺寸。模型包络和商品规格不一致时，两者分别说明；缺失维度标记暂定。
7. 遇到验证码或登录验证，交给用户完成；不绕过、不保存会话。等待期间继续已有照片比对与建模，记录尚未核验的候选，不能把旧记录冒充刚刚搜索所得。

## 入库与模型联动

- 将价格、跳转链接、产品介绍、评论情况保存到独立字段，适配现有四栏 UI。
- 用稳定 ID 关联本地图、商品数据、专用模型与布局实例。新增商品后同步库与默认摆放，但不擅自购买或提交订单。
- 获得图片后先看再做网格。把沙发脚型、靠垫数量、扶手厚度和金属框架等写成模型检查点。正面图无法证实的背面应注明近似。
- 标明 `exact-confirmed` / `similar` / `unverified` 的匹配程度；精确同款须有足够的型号、规格或厂家证据，仅外形像不够。
- 本地收集的商品照片不自动变成开源授权素材。保留来源；公开包用获许可图片或占位图，不把商家素材声明为自己的 MIT 作品。

## 验收

交付每个候选的证据和不确定性，指出默认选中款的理由。验证 URL 格式与本地图片路径；如果这次没有在线打开链接，只能说“记录已保留”，不能说链接仍有效。在项目中新增商品后运行数据检查、模型包络检查，再进行原图/模型视觉比对。
